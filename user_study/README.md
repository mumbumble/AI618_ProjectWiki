# 사용자 스터디

참가자에게 보내는 스터디 페이지입니다. `projectwiki_study.html` 하나를 브라우저로 열면 과제, 질문, 결과 제출까지 끝납니다. 인터넷이 필요합니다(vis-network 등을 CDN에서 불러오고, 결과를 구글 폼으로 보냄).

화면은 팀 뷰어(`projectwiki/srcs/view_template.html`, main `aeebcf0`)의 디자인과 동작을 따랐습니다. 데이터는 실제 시스템 출력이 아니라 `benchmark/gt/`의 정답 그래프를 씁니다.

## 진행 순서 (약 30분)

| 단계 | 폴더 · 목적 | 하는 일 |
|---|---|---|
| 시작 | | 이름(닉네임)·이메일, 과정·정리 방식·폴더 크기 3문항, 동의 두 항목 |
| 과제 1 앞부분 | plant(`leafproto_project`) · 발표 준비(`talk`) | 폴더 소개 → 파일 탐색기만 보고 4지선다 2문항 |
| 도구 연습 | sleep(`stat_hw_sleep`), 점수·시간 표시 없음 | 폴더 소개 → 따라 하기 5단계(그룹 → 파일 → 연결선 → 그룹 카드 → 지정한 연결 숨기기) → 연습 문제 2개(정답과 찾는 법 알려 줌, 다시 풀기 가능) |
| 과제 1 뒷부분 | plant · 발표 준비 | 그래프 도구로 4지선다 1문항(결과 표를 만든 코드) + 파일 고르기 1문항 |
| 과제 1 소감 | | 7점 척도 + 이유 |
| 과제 2 | plant · 인수인계(`handover`) | 필요 없는 연결 2개 숨기기 → 시스템 제안 6개 판단 |
| 과제 2 소감 | | 정리 전/후 그래프(숨긴 연결 빨간 점선, 목록) 비교, 7점 척도 + 이유 |
| 마지막 질문 | | 7점 척도 2문항, 좋았던 점·불편했던 점 |
| 끝 | | 결과가 폼 A로 자동 제출됨. 무작위 제안이 섞여 있었다고 알림. 본인 폴더 보내기(폼 B) 또는 하지 않고 마치기 |

- 과제 1 앞부분 안내 창은 '이 스터디에서 하는 일'(도구 소개, 전체 순서, 단계 진행 방식)부터 시작합니다. 이후 단계의 안내 창 맨 위에는 방금 끝난 것과 다음에 할 것, 전체 중 현재 위치가 나옵니다.
- 폴더를 처음 보는 단계(과제 1 앞부분, 도구 연습) 앞에는 폴더 소개(구성, 대략의 흐름)가 먼저 나옵니다. 과제 중에도 위쪽 [폴더 소개]로 다시 열 수 있습니다.
- 각 단계 시작 전에 안내 창이 뜨고, [시작하기]를 누른 시점부터 시간을 잽니다. 안내 창이 떠 있는 동안에는 질문이 보이지 않습니다. 도구 연습은 시간을 화면에 보여 주지 않고 기록만 합니다.
- 과제 1은 보기를 누르면 다음 질문으로 넘어가고, [← 이전 질문]으로 돌아가 답을 바꿀 수 있습니다. 질문별 시간과 연 파일 수는 머문 시간만큼 더해집니다. 마지막 질문 뒤에는 [다음 단계로]를 눌러야 넘어갑니다.
- 그래프는 같은 그룹끼리 모이게 배치하고, 연결 3개 이상인 파일만 이름을 보여 줍니다. 마우스를 올리거나 선택하거나 확대하면 나머지 이름도 보입니다.
- 질문과 안내는 화면 아래 떠 있는 카드에 나옵니다. [접기]로 줄일 수 있습니다.
- 진행 중에 창을 닫거나 새로고침하려 하면 브라우저가 한 번 더 묻습니다.

## 결과 받기

마지막 질문에서 [제출하기]를 누르면 구글 폼 A(참가자에게 안 보임)로 자동 제출됩니다. 응답 시트에서 바로 정리할 수 있게 값마다 열이 하나씩입니다.

- 참가자: 이름, 이메일, 과정, 정리 방식, 폴더 파일 수, 전체 시간
- 과제 1: 앞·뒤 정답 수, 평균 시간, 연 파일 수, 도구 연습 시간, 소감(−3~+3), 이유
- 과제 2: 시스템 제안 동의 수, 무작위 제안 동의 수, 소감, 이유
- 마지막 질문: 7점 척도 2개, 좋았던 점, 불편했던 점
- 전체 기록(JSON): 클릭 기록(파일·그룹·연결 열기, 숨기기, 교정 버튼, 보기 전환, 검색), 과제 2 제안 6개 각각의 출처와 판단, 정답 기준으로 맞는 제안이었는지 등 나머지 전부

전송에 실패하면 끝 화면에 [다시 보내기]와 [파일로 저장]이 나옵니다.

## 과제 2 제안 방식

참가자가 연결 2개를 숨기면 제안 6개를 섞어서 보여 줍니다. 출처는 표시하지 않습니다.

제안 설명은 6개 모두 같습니다("시스템이 인수인계에 필요 없어 보인다고 고른 연결입니다").

- **시스템 제안 3개:** 숨긴 연결과 비슷한 연결. 점수 = 2×(같은 그룹 쌍) + (파일 공유) + (같은 관계 종류), 2점 이상 중 상위 3개. 정답 정보는 쓰지 않습니다.
- **비교용 3개:** 아직 보이는 연결 중 무작위.

모의 실험(불필요 연결 2개를 무작위로 숨긴다고 가정, 1,500회)에서 인수인계 목적 기준으로 시스템 제안의 94%, 무작위의 44%가 실제로 불필요한 연결이었습니다. 발표 준비 목적은 연결 45개 중 31개가 불필요라 무작위도 65%가 맞아서 차이가 작습니다. 그래서 과제 2는 인수인계 목적을 씁니다.

## 다시 만들기

```bash
python user_study/build_study.py            # user_study/projectwiki_study.html 생성
```

| 파일 | 내용 |
|---|---|
| `study_template.html` | 화면과 동작 (HTML/CSS/JS) |
| `build_study.py` | 정답 그래프와 폴더 내용을 읽어 템플릿에 넣음. 단계·문항·정답·상황 문구는 `STEPS`, 보여 줄 폴더 이름은 `NAME`, 폴더 소개는 `INTRO`, 구글 폼 주소와 문항 ID는 `FORMS`에 있음 |
| `study_text.py` | 파일 요약, 그룹 설명, 연결 설명(한국어) |
| `projectwiki_study.html` | 결과물 (생성 파일, 참가자에게 보내는 파일) |

과제 문항이나 상황 문구는 `STEPS`, 시작·마지막 질문은 `study_template.html`의 `PROFILE`·`SURVEY`, 단계 안내는 `BRIEFS`, 연습 단계는 `PSTEPS`, 그 밖의 화면 문구는 `study_template.html`을 고친 뒤 다시 만들면 됩니다. 폼 A의 문항을 바꾸면 `FORMS`의 ID도 다시 맞춰야 합니다.

## 남은 것

- 실제 시스템 출력으로 바꾸기: 지금은 정답 그래프를 그대로 보여 줍니다.
- 그룹 사각형: 같은 그룹끼리 모이게 했지만 연결이 많은 파일 근처에서는 다른 그룹 파일을 일부 감쌀 수 있습니다.
- 오프라인에서 쓰려면 라이브러리를 파일에 포함해야 합니다.
