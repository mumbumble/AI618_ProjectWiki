# 사용자 스터디 목업

참가자가 실제로 보게 될 화면을 클릭해 볼 수 있게 만든 목업입니다. `study_mockup.html` 하나만 브라우저로 열면 됩니다. 인터넷이 필요합니다(vis-network 등을 CDN에서 불러옴).

화면은 팀 뷰어(`projectwiki/srcs/view_template.html`, main `aeebcf0`)의 디자인과 동작을 따랐습니다. 데이터는 실제 시스템 출력이 아니라 `benchmark/gt/`의 정답 그래프를 씁니다.

## 진행 순서 (약 20분)

| 단계 | 폴더 · 목적 | 하는 일 |
|---|---|---|
| 시작 | | 동의 두 항목 |
| 과제 1 앞부분 | plant · 발표 준비(`talk`) | 파일 탐색기만 보고 4지선다 2문항 |
| 도구 연습 | sleep (점수 없음) | 그룹 선택 → 파일 열기 → 연결선 선택 → 연결 숨기기, 연습 문제 2개 |
| 과제 1 뒷부분 | plant · 발표 준비 | 그래프 도구로 4지선다 1문항 + 파일 고르기 1문항 |
| 과제 1 소감 | | 7점 척도 + 이유 |
| 과제 2 | plant · 인수인계(`handover`) | 필요 없는 연결 2개 숨기기 → 시스템 제안 6개 판단 |
| 과제 2 소감 | | 정리 전/후 그래프 비교, 7점 척도 + 이유 |
| 끝 | | 결과 JSON 저장 → 구글 폼 제출 |

- 각 단계 시작 전에 안내 창이 뜨고, [시작하기]를 누른 시점부터 시간을 잽니다.
- 질문과 안내는 화면 아래 떠 있는 카드에 나옵니다. [접기]로 줄일 수 있습니다.

## 기록되는 값

결과 JSON(`projectwiki_study_result.json`)에 단계별로 남습니다.

- 문항별 답, 정답 여부, 걸린 시간, 연 파일 수
- 클릭 기록: 파일·그룹·연결 열기, 숨기기, 교정 버튼, 보기 전환, 검색
- 과제 2: 직접 숨긴 연결, 제안 6개 각각의 출처(시스템/비교용)와 판단, 정답 기준으로 맞는 제안이었는지
- 소감 점수(−3~+3)와 이유

끝 화면의 요약 표는 목업에서 기록 항목을 보여 주려고 넣은 것입니다. 실제 스터디에서는 빼야 합니다.

## 과제 2 제안 방식

참가자가 연결 2개를 숨기면 제안 6개를 섞어서 보여 줍니다. 출처는 표시하지 않습니다.

- **시스템 제안 3개:** 숨긴 연결과 비슷한 연결. 점수 = 2×(같은 그룹 쌍) + (파일 공유) + (같은 관계 종류), 2점 이상 중 상위 3개. 정답 정보는 쓰지 않습니다.
- **비교용 3개:** 아직 보이는 연결 중 무작위.

모의 실험(불필요 연결 2개를 무작위로 숨긴다고 가정, 1,500회)에서 인수인계 목적 기준으로 시스템 제안의 94%, 무작위의 44%가 실제로 불필요한 연결이었습니다. 발표 준비 목적은 연결 45개 중 31개가 불필요라 무작위도 65%가 맞아서 차이가 작습니다. 그래서 과제 2는 인수인계 목적을 씁니다.

## 다시 만들기

```bash
python user_study/build_mockup.py            # user_study/study_mockup.html 생성
```

| 파일 | 내용 |
|---|---|
| `mockup_template.html` | 화면과 동작 (HTML/CSS/JS) |
| `build_mockup.py` | 정답 그래프와 폴더 내용을 읽어 템플릿에 넣음. 단계·문항·정답은 `STEPS`에 있음 |
| `study_text.py` | 파일 요약, 그룹 설명, 연결 설명(한국어) |
| `study_mockup.html` | 결과물 (생성 파일) |

문항이나 목적을 바꾸려면 `STEPS`를, 화면 문구는 `mockup_template.html`을 고친 뒤 다시 만들면 됩니다.

## 남은 것

- 실제 시스템 출력으로 바꾸기: 지금은 정답 그래프를 그대로 보여 줍니다.
- 끝 화면 요약 표 빼기, 결과 제출 방식 정하기(구글 폼).
- 그룹 사각형: 그래프 배치가 그룹 단위가 아니라서 다른 그룹 파일도 일부 감쌉니다.
- 오프라인에서 쓰려면 라이브러리를 파일에 포함해야 합니다.
