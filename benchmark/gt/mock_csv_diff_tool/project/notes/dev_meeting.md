## 2. 이슈 #42 검토

자료: `issues/issue_42.md`

- **제목**: read_table이 UTF-8 BOM이 있는 파일에서 첫 번째 컬럼명을 잘못 읽음
- **증상**: 헤더가 `id` 대신 `﻿id`로 표시됨. 그래서 `--key id`를 주면 `KeyError: 'id'`가 나고, 모든 행이 added + removed로 잘못 찍힘
- **재현**: BOM(EF BB BF) + `id,name\n1,Ann\n2,Bob\n` 파일을 만든 뒤 `read_table(path)`와 `diff_files(..., key="id")` 호출
- **보고자**: mina-dev (2026-09-12 접수), 영향 버전 0.3.0, 0.3.1
- **원인 (이서연 분석)**: delimiter를 명시하면 `detect_encoding`을 건너뛰고 `encoding="utf-8"`로 열고 있었음
- **수정**: `detect_encoding`이 BOM을 보면 `"utf-8-sig"`를 반환하도록 변경. 2026-09-25 머지, 0.3.2에 포함
- **회귀 테스트**: `test_read_table_strips_bom_issue_42` 추가됨

**결정 사항**
- 0.3.2 수정은 이미 머지되었지만 릴리스 노트 항목이 빠져 있음. 0.4.0 변경 이력에 #42 항목을 추가하기로 함 (담당: 이서연)
- 보고자 mina-dev에게 0.3.2 설치를 안내하는 댓글을 달기로 함 (담당: 박지훈)

## 3. 벤치마크 검토

측정 조건은 다음과 같음.
- 입력: 5개 컬럼(id, name, amount, city, flag)의 랜덤 CSV, seed 7 고정
- 각 크기별 5회 실행의 중앙값(median)
- 측정 대상: 0.4.0 릴리스 브랜치 (0.3.2는 비교 기준)

| 입력 크기 (행) | 버전 | 소요 시간 (초) | 개선율 |
|---:|---|---:|---:|
| 10,000 | 0.3.2 | 0.21 | - |
| 10,000 | 0.4.0 | 0.10 | 약 2.1배 |
| 100,000 | 0.3.2 | 2.30 | - |
| 100,000 | 0.4.0 | 1.12 | 약 2.1배 |
| 1,000,000 | 0.3.2 | 25.40 | - |
| 1,000,000 | 0.4.0 | 12.70 | 2.0배 |

**논의 내용**
- 0.4.0에서 키 기반 정렬(keyed alignment)이 전 구간에서 약 2배 빨라짐. 김민준은 해시 인덱스 구성 부분을 줄인 효과라고 설명함
- 100만 행 기준 12.70초는 아직 목표에 못 미침. 0.5.0 목표는 **100만 행 8초 미만**으로 정함
- 최예린: 벤치마크 스크립트는 CI에서 주기적으로 돌리고, 결과 파일을 버전별로 누적하기로 함
- 메모리 측면에서는 키 인덱스를 메모리에 올리는 구조(D2)가 큰 입력의 병목이라는 의견이 나옴. 이 부분은 0.5.0 설계에서 다시 보기로 함
