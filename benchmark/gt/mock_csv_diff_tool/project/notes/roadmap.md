# csvdelta 로드맵

작성일: 2026-11-21
현재 버전: 0.4.0 (2026-10-30 릴리스, MIT 라이선스, Python 3.9 이상)

이 문서는 0.5.0부터 1.0.0까지의 계획을 정리합니다. 설계 문서에 적힌 구조(모듈, 데이터 흐름, 설계 결정 D1~D5)를 바꾸는 항목은 따로 표시했습니다.

## 1. 현재 상태

- **0.4.0**: `summary`, `patch` 명령 추가. keyed 정렬 속도 약 2배 향상.
- **0.3.2**: #42 BOM 헤더 버그 수정 (이서연). UTF-8 BOM 파일에서 첫 번째 열 이름이 `﻿id`로 읽히던 문제를 해결했고, 회귀 테스트가 추가되었습니다.
- **0.3.0**: 플러그인 시스템, excel 플러그인, html 출력, 설정 파일 지원.

## 2. 0.5.0 (목표 2027-01)

### 2.1 스트리밍 외부 정렬 diff

- `max_rows_in_memory` 제한을 없앱니다.
- 현재는 키 인덱스 전체를 메모리에 올리지만, 0.5.0에서는 두 파일을 키 기준으로 외부 정렬(external sort)한 뒤 순서대로 병합 비교합니다.
- `Differ.align_rows`를 다시 작성하고, `io` 모듈에 정렬용 임시 파일 쓰기 기능을 추가합니다.
- **설계 변경**: 설계 결정 D2("스트리밍 reader이지만 키 인덱스는 메모리에 둔다")를 바꿉니다. 키 인덱스도 디스크 기반으로 처리합니다.

### 2.2 열 단위 병렬 비교

- 셀 비교(`Differ.compare_cells`)를 열 단위로 나누어 프로세스 풀에서 실행합니다.
- 표준 라이브러리(`concurrent.futures`)만 사용합니다. 설계 결정 D1(pandas 없는 순수 표준 라이브러리 코어)은 유지합니다.

### 2.3 성능 목표

| 행 수 | 0.3.2 | 0.4.0 | 0.5.0 목표 |
|---|---|---|---|
| 10,000 | 0.21 s | 0.10 s | - |
| 100,000 | 2.30 s | 1.12 s | - |
| 1,000,000 | 25.40 s | 12.70 s | 8 s 미만 |

0.4.0 수치는 릴리스 브랜치에서 시드 7, 5회 중앙값으로 측정했습니다. 1M 행은 25.4초에서 12.7초로 2.0배 빨라졌습니다.

## 3. 0.6.0 (목표 2027-04)

### 3.1 플러그인 hook 도입

- 현재 플러그인은 `Differ`를 상속해서 `run`을 재정의합니다.
- 0.6.0에서는 hook 방식으로 바꿉니다. 플러그인이 읽기, 정렬 전 변환, 출력 단계에 등록하는 방식입니다.
- **설계 변경**: 설계 결정 D3("플러그인은 hook 대신 상속으로 확장한다")를 바꿉니다.
- 기존 상속 방식은 0.6.0에서 deprecated로 표시하고, 1.0.0 전에 제거 여부를 다시 검토합니다.
- entry-point 그룹 `csvdelta.plugins`는 그대로 유지합니다.

### 3.2 플러그인 작업

- excel 플러그인(`ExcelDiffer`)을 새 hook 방식으로 옮깁니다. 담당: 정우진
- Parquet 플러그인을 추가합니다. 담당: 정우진

## 4. 1.0.0 (목표 2027-09)

- **API 동결**: `diff_files`, `diff_tables`, `read_table`, `write_delta`, `summarize`, `DiffResult` 여섯 개 공개 이름을 1.0.0 이후 유지합니다.
- **CLI 고정**: `diff`, `summary`, `patch` 명령과 `--key`, `--delimiter`, `--encoding`, `--format`, `--config`, `--ignore-case`, `--tolerance` 옵션을 고정합니다.
- **JSON 스키마 고정**: delta JSON은 `version: 1` 스키마를 유지합니다. 구조가 바뀌면 `version`을 올립니다.
- 1.0.0 이후 공개 API의 호환되지 않는 변경은 major 버전에서만 합니다.

## 6. 위험 요소와 열린 질문

- 외부 정렬은 작은 파일에서 오히려 느릴 수 있습니다. 행 수가 적을 때는 기존 메모리 경로를 그대로 쓰는 방안을 검토합니다.
- 외부 정렬을 쓰면 정렬 순서와 `tolerance` 비교가 어긋날 수 있습니다. 숫자 키의 정렬 규칙을 먼저 정해야 합니다.
- hook 설계가 확정되기 전에는 0.5.0에 포함하지 않습니다. 0.6.0 일정이 밀리면 Parquet 플러그인을 먼저 내보냅니다.
- 병렬 비교를 도입하면 Windows에서 프로세스 시작 비용이 커질 수 있으므로, 최예린이 CI에서 플랫폼별 수치를 확인합니다.
