# trackslim 로드맵

이 문서는 trackslim의 다음 버전 계획을 정리합니다. 현재 구조와 동작은 설계 문서를 기준으로 하고, 여기서는 그 구조를 어떻게 바꿀지를 다룹니다.

## 현재 상태

- 최신 릴리스: 0.4.0 (2026-10-30)
- 0.4.0 주요 변경
  - 반복 스택(iterative stack) 기반 처리로 전환
  - 100,000 포인트 기준 1.77배 빠름 (3.512초 → 1.987초)
  - ElevationGuard 플러그인 추가
  - `stats` 명령 추가
- 2026-09-05 개발 회의에서 정한 목표(100,000 포인트 2.0초 이하)를 달성했습니다.

## 버전 계획

### 0.5.0 (목표 2026-12)

1. **CSV 내보내기**: Parquet 없이 CSV로 결과를 저장합니다. 표준 라이브러리 `csv`만 사용합니다.
2. **KML 리더**: 새 IO 계층으로 KML 파일 읽기를 지원합니다. GPX 리더와 같은 `Track` 객체를 반환해야 합니다.
3. **세그먼트 병렬 단순화**: 여러 `<trkseg>`를 병렬로 단순화합니다. 세그먼트 경계의 점은 양쪽 세그먼트에서 모두 유지합니다.

### 1.0.0 (목표 2027-03)

1. **안정 API 확정**: 패키지 최상위에서 내보내는 공개 이름과 시그니처를 고정합니다. 이후 변경은 주 버전에서만 합니다.
2. **지오데식 3D 거리**: 현재의 equirectangular 평면 투영을 지오데식 3D 거리로 바꿉니다. 설계 문서의 Limitations 항목을 해소하는 작업입니다.
3. **엔트리 포인트 기반 플러그인 레지스트리**: 외부 패키지가 entry point로 플러그인을 등록하도록 합니다. 지금의 내부 `PLUGINS` 딕셔너리는 이 레지스트리로 대체합니다. CLI의 `--plugin <이름>` 사용법은 그대로 유지합니다.

## 아키텍처 변경 계획

설계 문서의 3계층 구조(IO, Core, Plugins + 상단 CLI)는 유지합니다. 아래는 각 계층에서 바뀌는 부분입니다.

### IO 계층
- KML 리더를 추가합니다.
- GPX와 KML이 함께 쓰는 로직은 공용 헬퍼로 분리합니다. 대상은 타임스탬프 파싱(Z 접미사 포함), 세그먼트 병합, `<ele>`가 없는 점의 기본값 처리입니다.
- 이슈 #37(다중 세그먼트에서 마지막 점이 빠지던 문제)의 교훈을 반영해, KML에도 같은 형태의 회귀 테스트를 둡니다.

### Core 계층
- `Simplifier`의 생성자와 `simplify(track) -> Track` 시그니처는 바꾸지 않습니다.
- `perpendicular_distance_m`의 내부 계산만 지오데식 방식으로 바꿉니다. 호출하는 쪽의 인터페이스는 그대로입니다.
- 세그먼트 단위 병렬 처리는 `simplify` 안에서 수행하고, 결과를 원래 순서대로 합칩니다.

### 데이터 흐름 변경
기존 흐름은 `read_gpx → Track → Simplifier.simplify → write_gpx`입니다. 0.5.0 이후에는 다음과 같이 바뀝니다.

1. 리더(GPX 또는 KML)가 세그먼트 목록을 가진 `Track`을 만듭니다.
2. 세그먼트가 여러 개이고 병렬 옵션이 켜져 있으면 세그먼트를 나눠 단순화합니다. 그렇지 않으면 순차 처리합니다.
3. 결과를 세그먼트 순서대로 합쳐 `Track`으로 돌려줍니다.
4. 라이터(GPX 또는 CSV)가 결과를 저장합니다.

### Plugins 계층
- 플러그인 탐색을 entry point 방식으로 바꿉니다(1.0.0).
- 플러그인은 여전히 `Simplifier`의 하위 클래스여야 합니다.

## 위험 요소와 대응

- **지오데식 거리 도입으로 결과가 바뀜**: 허용 오차 기준 결과가 달라질 수 있습니다. 1.0.0 전에 기존 테스트 기대값과 벤치마크 결과를 다시 검토합니다.
- **작은 파일에서 병렬 처리 오버헤드**: 세그먼트가 적거나 점 수가 적으면 순차 처리를 유지합니다. 기준값은 벤치마크로 정합니다.
- **플러그인 탐색 방식 변경으로 기존 플러그인이 깨짐**: 0.5.0 이전 버전에서 내부 딕셔너리 이름과 entry point 이름을 모두 인식하는 기간을 둡니다.
- **KML 구조 차이**: KML은 GPX와 좌표 순서와 시간 표현이 다릅니다. 리더 테스트 샘플을 별도로 준비합니다.
