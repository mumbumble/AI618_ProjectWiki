# 파일럿 세션 노트

**프로젝트**: "Explain Yourself, Reviewer" – ReviewLens 설명 방식이 개발자의 신뢰와 리뷰 정확도에 미치는 영향
**기간**: 2026-03-12 ~ 2026-03-13
**참가자**: 3명 (파일럿-1, 파일럿-2, 파일럿-3). 본 데이터(P01–P10)에는 포함하지 않음.
**프로토타입 버전**: v0.3 (파일럿 당시) → v0.4 (파일럿 후 수정)
**작성자**: Han Ji-woo

---

## 1. 목적

- 90분 세션 흐름(동의 10분, 훈련 10분, 조건별 약 15분 × 3, 반구조화 인터뷰 15분)이 실제로 90분 안에 끝나는지 확인
- 과제 난이도와 제한 시간(과제당 8분, 480초)이 적절한지 확인
- 프로토타입 화면에서 조건 간 차이가 없는 버그가 있는지 확인
- 설문 문항(Q1–Q8)과 인터뷰 가이드 문항의 이해도 확인

## 2. 세션 진행 요약

| 항목 | 2026-03-12 | 2026-03-13 |
|---|---|---|
| 참가자 | 파일럿-1, 파일럿-2 | 파일럿-3 |
| 전체 소요 | 약 88분 | 약 94분 |
| 제한 시간 초과 | 0건 | 1건 (T3, 14분 사용) |

- 세 조건 모두 설명 패널이 정상적으로 표시되었는지 확인함.
- 조건 순서는 라틴 방격 회전 규칙을 따라 배정했음 (파일럿-1: terse → rationale → trace, 파일럿-2: terse → trace → rationale).
- 세션 시간은 목표 90분을 약간 넘김. 설문 응답 시간이 조건당 3–4분 걸렸고, 인터뷰에서 말이 길어지는 경향이 있었음.

## 3. 발견 문제 1: T3 (레이스 컨디션, 캐시 갱신) 과제

**관찰**
- 원래 T3 PR diff가 420줄이었음. 파일럿-3이 T3를 시작한 뒤 14분이 지나도 리뷰를 끝내지 못함.
- 파일럿-1, 파일럿-2도 T3에서 마지막 몇 분을 파일 전체 훑기에 썼다고 말함.
- 지시문에 "변경된 모든 함수를 검토하라"는 표현이 있었는데, 참가자들이 이를 "전체 파일 검토"로 받아들였음.

**조치**
1. T3 diff를 420줄에서 160줄로 축소. 시드된 결함 3개는 그대로 유지.
2. 지시문 재작성: "이 PR에서 바뀐 캐시 갱신 로직(락 획득 및 해제 구간)을 중심으로 검토하라"로 수정.
3. 제한 시간은 8분(480초)으로 고정. 파일럿에서는 시간 기록이 일관되지 않았으므로, 본 수집 전에 타이머 표시와 로그 기록 시점을 다시 확인할 것.
4. 수정한 T3 변형(A/B/C)은 세 세트 모두 같은 줄 수 범위(155–165줄)에 맞춰 만들 것.

**남은 확인 사항**
- 160줄 변형에서도 파일럿-3 수준의 참가자가 8분 안에 끝낼 수 있는지는 본 수집에서 다시 봐야 함.
- 다른 과제(T1, T2, T4)는 파일럿에서 시간 초과가 없었음.

## 4. 발견 문제 2: 프로토타입 설명 캐시 버그 (v0.3)

**관찰**
- 참가자가 "다음 댓글" 버튼을 빠르게 연속으로 누르면, 새 댓글 아래에 직전 댓글의 설명이 표시됨.
- 파일럿-2가 "앞에 있던 댓글 설명이 다시 나온다"고 두 번 언급함. 본인이 설명을 잘못 읽었다고 생각해서 바로 정정하지 못했다고 함.

**원인**
- 설명 캐시의 키가 댓글 인덱스만으로 구성되어 있었음.
- 조건(terse/rationale/trace)이나 댓글 식별자가 키에 포함되지 않아, 빠른 전환 시 이전 항목의 캐시가 재사용됨.

**조치 (v0.4)**
- 캐시 키를 (condition, comment_id) 쌍으로 변경.
- 이 수정은 v0.4 배포에 포함됨. 본 수집은 v0.4로 진행.

**주의**
- 이 버그는 설명 내용을 잘못 보여주기 때문에 신뢰 측정치를 직접 왜곡할 수 있음. 파일럿 데이터는 본 분석에서 제외했으므로 영향 없음.
- 본 수집 로그에서 조건과 댓글이 어긋난 기록이 없는지 분석 전에 점검할 것.

## 5. 설문 및 인터뷰 관찰

- Q4("이유를 이해했다")와 Q5("설명이 잘못된 부분을 알아채는 데 도움이 되었다")는 파일럿-1이 문항 의미를 두 번 물어봄. 본 수집 안내문에 예시를 덧붙이는 것을 검토할 것.
- Q7(정신적 노력)은 높을수록 노력이 많이 들었다는 뜻이라고 설문 전에 한 번 더 안내해야 함. 파일럿-2가 점수를 반대로 이해한 것 같아 보였음.
- 인터뷰에서 파일럿 참가자들은 trace 조건의 하이라이트와 실행 흐름 설명이 "검증에 가장 도움이 되었다"고 말함. 다만 긴 설명을 읽는 데 시간이 걸린다는 의견도 있었음.
- 세 명 모두 terse 조건에서 "왜 이런 지적을 했는지 모르겠다"는 말을 함.
