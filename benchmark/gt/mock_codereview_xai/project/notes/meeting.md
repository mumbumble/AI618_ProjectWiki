## 2. 연구 개요 및 수집 현황

- 연구 질문: AI 코드리뷰 어시스턴트의 설명 방식이 개발자의 신뢰와 리뷰 정확도에 어떤 영향을 주는가?
- 조건: terse / rationale / trace (피험자 내 설계)
- 참여자: 10명 (P01–P10), 24–38세(중앙값 29), 경력 2–11년(중앙값 5), 남 6 / 여 4
- 과제: T1 pagination off-by-one, T2 SQL injection, T3 race condition in cache refresh, T4 unclosed file handle
- 실행: 참여자당 4과제 × 3조건 = 12회. 작업 로그 120행, 설문 30행. 과제 제한 시간 8분(480초)
- 조건마다 PR 변형(A/B/C)을 사용
- 순서 균형: 6개 순열을 라운드로빈으로 배정 (P01 terse-rationale-trace, P02 terse-trace-rationale, ..., P07은 P01과 동일 순서)
- 수집 기간: 2026-04-06 ~ 2026-05-15
- 파일럿(2026-03-12/13, 3명, 본 데이터 제외): T3 diff를 420줄에서 160줄로 축소하고 지시문을 수정한 뒤 8분 제한을 고정함. 파일럿 v0.3에서 "Next comment"를 빠르게 누르면 이전 댓글 설명이 보이는 버그가 있었고, v0.4에서 캐시 키를 (condition, comment_id)로 바꿔 수정함. 본 연구는 v0.4로 진행

## 3. 주요 결과

### 3.1 신뢰 (H1)

신뢰 composite = mean(Q1, Q2, Q3)

| 조건 | 신뢰 composite | 95% CI 반폭 |
|---|---|---|
| terse | 3.70 | 0.41 |
| rationale | 4.90 | 0.36 |
| trace | 5.67 | 0.30 |

- Friedman χ²(2) = 13.00, p = .002, Kendall W = 0.65 (n = 10)
- 판단: H1 지지 (trace > rationale > terse)

설문 항목별 평균 (terse / rationale / trace)

| 항목 | terse | rationale | trace |
|---|---|---|---|
| Q1 신뢰 | 3.9 | 5.0 | 5.6 |
| Q2 신뢰 | 3.4 | 5.1 | 5.9 |
| Q3 신뢰 | 3.8 | 4.6 | 5.5 |
| Q4 이해 | 3.2 | 5.2 | 6.0 |
| Q5 보정(calibration) | 3.1 | 4.4 | 5.5 |
| Q6 확신 | 3.6 | 4.8 | 5.4 |
| Q7 작업 부담 (높을수록 노력 많음) | 4.9 | 4.5 | 3.8 |
| Q8 사용 의향 | 3.5 | 4.6 | 5.3 |

### 3.2 리뷰 정확도 (H2)

- 오류 = 놓친 시드 결함 + 잘못된 AI 제안 수락 (과제당 0–3), 정확도 = 1 − errors/3
- 과제당 평균 오류: terse 1.30, rationale 0.95, trace 0.65 (총합 52 / 38 / 26)
- 정확도: 56.7% / 68.3% / 78.3%
- Friedman (참여자별 평균 오류) χ²(2) = 6.20, p = .045, Kendall W = 0.31
- Wilcoxon trace vs terse: W = 5, p = .020 (**보정 전 값**)
- 판단: H2 지지. 다만 보정 전 p이므로 보고 시 명시 필요

### 3.3 작업 시간

- 과제당 평균 시간: terse 212.4 s / rationale 187.6 s / trace 163.9 s (총합 8496 / 7504 / 6556 s)
- Friedman (참여자별 평균 시간) χ²(2) = 7.20, p = .027, Kendall W = 0.36
- 순위합 (1 = 가장 빠름): trace 14, rationale 20, terse 26

| 비교 | W | p | Holm 보정 p (3 비교) |
|---|---|---|---|
| trace vs terse | 3 | .010 | .030 |
| trace vs rationale | 11 | .053 | .106 |
| rationale vs terse | 13 | .085 | .106 |

- 해석: trace가 가장 빠름. 보정 후 유의한 차이는 trace vs terse뿐

## 4. 교수님 피드백 및 결정 사항

1. **Holm 보정**: 시간 post-hoc 비교에 적용 완료. 결과 표에 보정 p를 함께 표기
2. **Kendall W 보고**: 모든 Friedman 결과에 W 포함
3. **시드 결함 한계**: PR이 시드 결함 기반이므로 실제 리뷰 상황의 대표성에 한계가 있음. 결과 논의에 명시
4. **N=20 재현 연구**: 2027년 진행 여부를 검토
5. **선행연구 비교**: Cho & Baek (2024)는 긴 설명이 수락률을 17%, 리뷰 시간을 22% 높인다고 보고함. 본 연구의 trace는 근거 연결형 설명인데도 시간이 줄었음. 이는 설명의 길이보다 근거 연결 방식이 중요할 수 있다는 가설적 해석이며 검증이 필요함
6. **신뢰와 정확도의 관계**: 신뢰가 올랐다고 잘못된 제안을 더 많이 수락했는지 확인 필요. 오류를 놓친 결함과 잘못된 수락으로 나눠 분석하기로 함
