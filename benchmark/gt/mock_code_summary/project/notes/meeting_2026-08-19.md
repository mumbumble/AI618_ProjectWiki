## 2. 메인 결과 검토

지표는 BLEU-4(0~100 스케일, corpus-level)이며, 95% bootstrap CI를 함께 보고한다.

intra_repo 설정 결과는 다음과 같다.

| 방법 | BLEU-4 | 95% CI |
|---|---|---|
| Transformer | 20.4 | [20.0, 20.8] |
| RetroSum | 22.6 | [22.2, 23.0] |
| CodeSibling | 23.7 | [23.3, 24.1] |
| RepoSum | 26.1 | [25.7, 26.5] |

cross_repo 설정 결과는 Transformer 18.2, RetroSum 20.1, CodeSibling 20.9, RepoSum 22.4이다.

- intra_repo에서 RepoSum은 최고 baseline(CodeSibling 23.7)보다 +2.4 높다.
- RepoSum CI [25.7, 26.5]와 CodeSibling CI [23.3, 24.1]이 겹치지 않아 차이는 bootstrap 기준으로도 유의하다고 보기로 했다.
- v1(2026-06-30) 수치와 비교하면 RepoSum intra 25.2 → 26.1, cross 21.7 → 22.4이고, CodeSibling은 intra 23.5 → 23.7, cross 20.8 → 20.9로 바뀌었다. v2에는 현재 수치만 싣기로 했다.
- v1에는 baseline이 Transformer와 CodeSibling 두 개뿐이었다. v2에서는 RetroSum을 포함해 세 개로 늘린다.

## 3. Ablation 계획

이번 회의에서 확정한 ablation은 아래 네 가지다. 각 항목은 전체 RepoSum에서 한 가지 구성요소만 제거한 설정이며, intra_repo BLEU-4 기준이다.

| 설정 | BLEU-4 | 전체 대비 |
|---|---|---|
| Full RepoSum | 26.1 | - |
| w/o repo scope (저장소 구분 없이 전체 대상 global retrieval) | 24.0 | -2.1 |
| w/o gated fusion (단순 concatenation) | 24.8 | -1.3 |
| w/o L_ret (사전학습 후 고정된 retriever) | 25.0 | -1.1 |
| w/o call-graph positives (L_ret의 positive를 random으로 교체) | 25.3 | -0.8 |

간단한 분석은 다음과 같이 정리했다.

- 저장소 범위(repo scope)가 가장 큰 기여를 한다. 범위를 풀면 -2.1로 가장 많이 떨어진다. 같은 저장소 안의 함수가 네이밍 규칙과 도메인 어휘를 공유하기 때문이라는 해석이 유력하다.
- gated fusion을 단순 concatenation으로 바꾸면 -1.3이다. 최유진이 sibling 품질이 낮은 샘플에서 gate 값이 작아지는지 확인해 보기로 했다. gate는 noisy sibling에서 특히 효과가 클 것으로 예상한다.
- L_ret을 제거하면 -1.1이다. retriever를 같이 학습하는 효과가 실재한다는 근거가 된다.
- call-graph positive를 random으로 바꾸면 -0.8이다. 효과는 작지만 방향은 일관적이므로 논문에 그대로 싣는다.
- k 실험도 같이 정리한다. k=4에서 최고점을 찍고, k가 커지면 RepoSum은 완만하게, baseline은 더 빠르게 떨어진다. k별 BLEU-4 그래프는 한지우가 다시 그린다.
