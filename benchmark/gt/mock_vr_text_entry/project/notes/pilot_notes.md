# VRType 파일럿 세션 노트

- 기간: 2026-08-25 ~ 2026-08-28
- 참가자: 4명 (파일럿 참가자는 A–D로 기록, 본 연구 코드 P01–P16과 별개)
- 앱 버전: v0.3.2 (본 연구는 v0.3.3 사용)
- 진행: 최민준 (파일럿 진행, RA)
- 목적: 세션 시간, 작업 난이도, 장비 및 앱 동작 확인

## 1. 세션 구성

- 조건 순서는 Latin square에 따라 배정 (A, C는 ray 먼저 / B, D는 swipe 먼저)
- 각 조건 전 3분 연습 제공
- 각 조건 내에서 T1–T4 순서로 진행
- 세션 최대 60분 기준을 지켰고, 4명 모두 60분 이내에 종료
- 세션 끝에 조건별 설문(Q1–Q8)과 짧은 인터뷰 진행 (인터뷰는 한 명당 약 10분)

## 2. 작업별 관찰

| 작업 | 관찰 내용 |
|---|---|
| T1 (짧은 일상 문장, 5단어) | 큰 문제 없음. 두 방식 모두 연습 후 빠르게 익숙해짐 |
| T2 (두 문장 메시지, 약 60자) | 시간이 가장 많이 걸림. swipe에서 단어 후보 선택 실수가 자주 보임 |
| T3 (12자 무작위 문자열) | **문제 발생** (아래 3절 참조) |
| T4 (URL) | 구두점과 슬래시 입력에서 ray는 키 전환이 잦아 느렸음 |

## 3. T3 문제와 작업 변경

- 원래 T3은 12자 무작위 문자열이었음
- 파일럿에서 4명 중 3명이 작업을 포기하거나 2분 넘게 걸림
- 피로와 좌절감이 커서 조건 비교가 어려울 것으로 판단
- 대안으로 8자 문자열(숫자 1개, 기호 1개 포함)로 변경
- 변경 후 T3은 "비밀번호처럼 보이는 짧은 문자열" 입력 과제로 유지
- 본 연구 작업 목록에도 변경된 T3 조건을 반영함

## 4. 앱 버그 (v0.3.2)

- 증상: swipe 모드에서 Backspace를 누른 뒤 이전 stroke buffer가 비워지지 않음
- 결과: 다음 stroke를 입력하면 직전 단어가 한 번 더 붙음 (단어 중복)
- 참가자 B, D에게서 두 차례 확인됨
- 참가자들이 중복을 알아채지 못하고 그대로 Enter를 누른 경우가 있어 오류 수 집계에 영향을 줌
- 조치: Backspace 처리 시 `clear_stroke_buffer()`를 호출하도록 수정, v0.3.3에 반영
- 본 연구는 v0.3.3으로 진행

## 5. 장비 및 세션 관찰

- Aurora V2 헤드셋의 hand tracking은 대체로 안정적이었음
- 참가자 C는 swipe T2 중 짧게 손 인식이 끊겼음 (본 연구에서도 같은 현상이 나올 수 있으므로 로그에 메모 필요)
- ray 모드에서 햅틱 피드백(20 ms)은 참가자들이 좋게 평가함
- swipe 모드에서 후보 바(상위 3개 단어)를 보지 않고 공백만 누르는 경우가 있었음 → 설명 문구 보강 필요
- 팔 피로: 두 조건 모두 2분 이상 한 손을 들고 있으면 불편하다는 의견이 있었음, 특히 swipe

## 6. 파일럿 결과 (참고용)

- 파일럿 n=4, 앱 v0.3.2 기준이므로 통계 분석에는 사용하지 않음
- 평균 작업 시간 대략 ray 45초, swipe 38초 (수치는 대략값)
- 이 수치는 최종 결과에서 제외하고, 방향성 확인 용도로만 기록
